# clip-sync：2026-10-04 審查修正紀錄

## 修正內容

| 原問題 | 修正行為 |
|---|---|
| 外部同步覆蓋尚未儲存的編輯 | 輪詢不替換本機未儲存內容，儲存時核對版本；衝突另存本機副本 |
| 新增 clip 遺失舊內容 | 新增前先完成儲存，失敗即保留原檔案 |
| 關閉視窗遺失最後輸入 | 關閉按鈕及 WM_DELETE_WINDOW 共用儲存流程，失敗時不關閉 |
| 寫入失敗後切換造成遺失 | 保留編輯並安排重試；儲存成功才切換，讀取成功才啟用目標檔案 |
| 多機共享暫存檔互相干擾 | 唯一暫存檔、共享排他鎖及鎖內版本驗證；失敗時清理自己持有的資源 |
| EXE 打包漏模組 | staging 補齊 settings_manager、ui_settings，打包前檢查所有模組匯入 |

配套修正：新增檔案改用排他建立，讀取不再重建遭刪除的檔案；設定改為原子寫入，打包後保存於 EXE 旁並相容舊設定。建置不再強制終止編輯器，也不再刪除最終部署目錄。

## 自動驗證

- 使用 Python 3.12 執行標準函式庫 unittest，22 個回歸測試全部通過。
- 回歸測試使用 TemporaryDirectory，不碰共享磁碟或實際使用者設定。
- UI 測試以替身執行真實流程方法；並行寫入測試使用執行緒控制交錯順序。
- 模擬建置腳本的 staging 複製清單，確認 main、ui_settings、settings_manager 可正常匯入。
- 執行 compileall 檢查全部 Python 檔案語法。

## Windows 驗收步驟

1. 輸入後立即新增 clip 或關閉，再開啟確認文字已保存。
2. 兩台電腦編輯同一個 clip，確認原檔與 conflict 副本均保留內容。
3. 中斷共享資料夾連線，確認編輯不消失、切換與關閉被阻止；恢復連線後確認重試成功。
4. 執行 build_exe.bat，啟動 EXE 並開啟設定面板，確認設定保存於 EXE 旁。
5. 重新建置，確認既有 settings.json 與使用者檔案仍在。

本執行環境無 Windows 桌面與真實 SMB，以上人工驗收未執行。排他鎖只協調採用新版程式的寫入者；外部編輯器與舊版程式不遵守鎖。網路 I/O 仍在 Tk 主執行緒執行，慢速或斷線共享磁碟可能造成暫時介面停頓。
